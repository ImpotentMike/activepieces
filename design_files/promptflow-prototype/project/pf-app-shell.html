Purpose

What the shell is and isn't

A composition, not a component. Wraps three primitives — [PromptFlow] Side Nav, the page header, the content container — and locks the relationship between them so every screen has consistent chrome.

It defines where things go (sidebar left, header top, content centre) and how much room they get (the layout tokens below). It never defines what goes inside the content area — that's the page's job.

Props / variants

API surface

  • sidebarCollapsedfalse (default, 264px) · true (64px icon-only). Toggle from the brand row button.
  • role"builder" · "admin" · "superadmin". Only superadmin sees the Superadmin Settings row.
  • crumbsArray of {label, href, kind}. Last item is the current page — never a link.
  • titlePage title. Wraps to 2 lines max, then truncates.
  • subtitleOptional 1-line description.
  • primaryActionOptional button slot on the right of the header. One primary action max.
  • projectTabsOptional array. When present, an extra 44px tab row sits below the title row.
  • state"ready" · "loading" · "empty". Drives content slot; chrome stays identical.
Accessibility

Keyboard, ARIA, focus

  • landmarks<aside aria-label="Primary navigation">, <header>, <main> — three discoverable regions.
  • tab orderBrand → collapse toggle → nav items (top-to-bottom, sub-items inline) → user → breadcrumbs → header actions → project tabs → content.
  • aria-current="page" on the active sidebar item and the active breadcrumb.
  • aria-expandedOn Projects nav item; reflects whether the sub-list is open.
  • tooltipsCollapsed sidebar tooltips appear on hover and keyboard focus. Tooltip is role="tooltip"; nav item carries the source of truth as aria-label.
  • loading regionSkeleton has role="status" with a specific aria-label ("Fetching last 100 runs") — not a generic "Loading…".
  • focus rings3px var(--fr-primary) on every interactive element. Never suppressed.
  • reduced motionSidebar collapse transition and skeleton shimmer respect prefers-reduced-motion.
PRD principles served

Design choice → principle

  • consistent chromeConfidence through clarity The shell is identical across Loading, Empty, and Ready. Users always know where they are and what they can do.
  • no dead-endsZero dead-ends Empty state always offers a next action ("Run a workflow now"). Loading shows a specific label, not a spinner with no information.
  • tab nav for projectsProgressive disclosure Workflows / Run History / Project Settings live inside the project, not as top-level nav — surface only what's relevant to where you are.
  • role-awareTrust and safety Superadmin items don't render for Builder/Admin — invisible, not just disabled.
  • specific copyGuided, not technical "Create workflow" not "+ New". "Fetching last 100 runs" not "Loading…". Crumb shows the project mark + name, not a UUID.
  • predictable widthsFast, predictable feedback Layout tokens are fixed: pages don't reflow when content loads.

Layout token reference Lock these before building dependent components. All measurements in CSS pixels.

Token Value Rationale
--shell-sidebar-w 264px Holds 14px nav labels + 18px icon + 12px gutter + a 2-digit count badge without truncating. Wider than MyDS reference 240 to give Projects sub-items breathing room.
--shell-sidebar-collapsed-w 64px 18px icon centred in a 40px hit target with 12px gutter on each side. Smallest comfortable touch target.
--shell-header-top-h 48px Breadcrumb row. 13px font · 32px horizontal padding. Separated from title row by a 1px gray-100 divider.
--shell-header-title-h 64px Title (22px) + optional 13px subtitle fit comfortably; 36px primary button has 14px breathing room. Reserved height even when subtitle is absent.
--shell-tabs-h 44px Only rendered when project tabs are present. 13.5px label + 10px vertical padding + 2px active underline.
--shell-content-max 1440px From PromptFlow Design System README. Tables and dashboards above this width feel scattered; this is the cap.
--shell-content-gutter 32px Outer padding around --shell-content-max. Never less than 24px.
--shell-content-min 960px Minimum content width at 1280px viewport with expanded sidebar. Below this, components must reflow.
— derived — 112px Total page header height without tabs (48 + 64). With project tabs: 156px (48 + 64 + 44).
— derived — 1280px Minimum supported viewport. At this width: 264 sidebar + 32 gutter + 960 min content + 32 gutter = 1288 — fits with 8px to spare.
