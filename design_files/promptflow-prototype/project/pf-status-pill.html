Purpose

What it is, where it goes

A glanceable, non-interactive label that resolves status in under half a second. Appears wherever a workflow or run is listed: the Workflows table, Run History, the Workflow Builder header, the Run Detail timeline, and template cards.

Eight semantic states across two scopes — workflow (Draft, Published, Paused, Unpublished) and run (Running, Success, Failed, Waiting).

Props / variants

API surface

  • statusOne of the 8 semantic values. Required.
  • size"md" (default, 18px line) · "sm" (16px line, for step nodes & dense lists)
  • withDottrue (default) · false for layouts where the fill is glanceable enough on its own
  • tooltipOptional string. Shown on hover/focus. Used for runtime context (e.g. "Waiting for CMU officer approval since 3:42pm").
  • aria-labelAuto-prefixed with the scope: "Run status: Running", "Workflow status: Draft".
Accessibility

WCAG AA, screen-reader notes

  • contrastAll fg/bg pairs meet WCAG AA (≥4.5:1 for the 12px label). Verified against MyDS 700-on-100 pairings.
  • colour ≠ sole cueStatus text is always present. The dot reinforces but never replaces the label.
  • live regionsrole="status" on Running and Waiting so SR users hear state transitions politely.
  • motionPulse respects prefers-reduced-motion — animation is suppressed entirely.
  • tooltip focusWrapper is tabindex="0" so keyboard users can reach tooltip content; tooltip has role="tooltip".
  • labelPill carries aria-label with scope prefix so context is read aloud even when surrounded by other pills.
PRD principles served

Design choice → principle

  • no icons insideConfidence through clarity Plain text is the only thing that needs to be read; the dot is colour-only redundancy.
  • no truncationFast, predictable feedback Labels chosen to fit the widest expected size — never let layout hide status.
  • pulse on Running, WaitingVisual transparency Live states look live; the user sees the system doing something.
  • tooltip on runtimeProgressive disclosure Specific runtime context (which step, since when, blocked on whom) is one hover away — not in the table by default.
  • non-interactiveTrust and safety Pills never trigger an action by themselves — actions live in the row menu and detail view.
  • plain languageGuided, not technical "Success", "Failed", "Waiting" — not "200 OK", "exec_err", "blocked_on_input".
  • Draft outlinedConfidence through clarity The ghost/outlined treatment signals "not yet committed" — visually distinct from Unpublished (was-live).

Colour-to-status mapping

MyDS tokens consumed by each status. Use this when rebuilding in Figma.

Pill Scope Background Text Dot Rationale
Running run primary-100 primary-800 primary-600 Brand blue = "system is doing work right now"
Success run success-100 success-700 success-600 MyDS success token, no modification
Failed run danger-100 danger-700 danger-600 MyDS danger token, reserved for true failure
Waiting run warning-100 warning-700 warning-600 Warning amber = "needs human attention"; pulse distinguishes from Paused
Draft workflow bg-white gray-700 gray-400 Outlined (gray-300 border) — signals "not yet committed". Visually distinct from Unpublished.
Published workflow success-100 success-700 success-600 Reuses Success palette — both mean "live and healthy"
Paused workflow warning-100 warning-700 warning-600 Shares Warning palette with Waiting; static dot (no pulse) distinguishes
Unpublished workflow gray-100 gray-600 gray-400 Washed gray fill = "was live, now off". Filled fill (vs. Draft's outline) signals it had a prior active state.
